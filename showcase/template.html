Modeling decisions

Expand a decision for the reasoning
01 · Aggregate before joining

Items and payments have different row grains. Aggregate each by order before joining, so multiple items and payments cannot multiply monetary amounts.

02 · Define the revenue proxy explicitly

Use delivered item prices, excluding freight and unobserved refunds. Payment totals may include canceled orders and do not establish accounting revenue.

03 · Identify returning people, not order identifiers

Use customer_unique_id across delivered orders. Olist customer_id identifies an order-specific customer record and would undercount returning customers.

04 · Bound AI and MCP access

GPT selects one approved intent and month. The application validates the selection and formats the query result. MCP exposes only get_monthly_revenue. The API key stays in the parent process, outside Git and browser code.

05 · Compare delivery dates

Estimated dates are stored at midnight. Compare calendar dates, so a delivery on the promised day is not incorrectly classified as late.

06 · Preserve exceptions and incomplete coverage

Retain payment discrepancies, uncategorized items and sparse boundary months. Mark the trend window explicitly; never replace an absent calendar month with the latest source month.
